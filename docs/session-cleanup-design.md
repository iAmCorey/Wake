# 本机会话文件清理：设计提案

状态：首版已实现，自动化验证与发布构建通过。2026-09-15。分支 `codex/session-cleanup`，独立 worktree `../vibex-session-cleanup`。

## 目标

清理本机过时或不再需要的会话文件，回收它们占用的磁盘空间。用户已明确不需要“仅从 Wake 隐藏”；本功能只有文件清理这一种动作。

设计重心：找到占空间的会话 → 看清内容及关联文件 → 选择清理 → 核对实际文件处理结果 → 完成空间回收。

“多久没更新”和“占多少空间”可以测量，“是否还有用”由用户判断。候选必须显示具体原因，不进行 AI 价值评分，也不自动删除。

## 现有基础

- 已有更新时间、消息量、文件大小、收藏、置顶及会话树关系。
- `workbench.rs::confirm_delete` 递归包含子会话，通过 adapter 的 `session_paths` 收集目标，再调用系统废纸篓和索引删除标记（tombstone）。
- 远程会话已有禁删限制；SQLite 虚拟路径目前仅写删除标记，不能回收源数据库空间，不应作为本功能的成功清理结果。
- 现有废纸篓服务缺少批量任务所需的逐目标执行反馈。源文件从废纸篓恢复后，Wake 的删除标记仍会阻止重新收录，需要提供显式恢复入口。

## 范围

只纳入 adapter 明确确认可独立清理的本机会话文件及其专属边车文件，包括属于这些会话的本地历史归档文件。

不纳入远程 host、远程镜像缓存、共享数据库、全局缓存、模型文件或项目工作目录。不能用删除整个数据库替代删除单条会话；不能把“只删除索引”算作磁盘清理。共享数据库清理需要另行设计官方支持的删除与空间压缩流程，第一版不支持。

所有目标都经过既有 Trash 和 tombstone 服务。不得读写凭证、修改 Codex SQLite、直接操作远端文件，或扫描与会话无关的目录。

## 入口与布局

入口固定放在**侧边栏底部工具条**，与现有 Insights、Settings、Refresh 并列。建议顺序为 **Insights / Clean Up / Settings / Refresh**，保持原有三个按钮的相对顺序。

- 使用清扫图标（Lucide `brush-cleaning`），tooltip 为 **Clean Up Sessions / 清理会话**；打开的是审阅界面，点击入口不执行删除。
- 沿用现有 44px 底部工具条、靠右排列、14px 图标和透明 ghost 样式；清理视图打开时图标使用 primary 色，语义与 Insights 激活态一致。
- 首次从这个全局工具入口进入时，来源范围不限，不继承侧栏的 Agent／项目限制。之后保留用户在 Filter 中主动设置的多选范围，并在页面摘要中展示名称或选中数量。
- 点击侧栏资料库导航即可退出清理并返回相应列表；保留普通列表的选择和滚动位置。仅查看清理再返回不会修改文件。
- 清理工具栏提供 Filter、Sort；不再把清理入口放到其更多菜单，也不新增永久的侧栏列表项。

采用主窗口内的临时清理模式，保留左侧资料库侧栏，主区域为与 Insights 同底色的单列表页面，不常驻分栏正文。

- 顶部显示页面标题和当前筛选条件，右侧集中 Filter、Sort 和刷新；标题下直接进入候选列表。
- 列表头展示筛选结果与全选，可清理体积放在未选中时的底部摘要。行内显示复选框、标题与 Agent / 项目、当前排序日期、文件体积；不放日期前缀、体积条和逐行网格线。
- 底部固定高度，通过选择状态切换内容：未选择时显示轻量引导与清理记录；选择后显示项数、实际会话数、体积、“取消选择”和“清理…”。
- 清理记录入口直接打开主区历史列表，空记录也可进入。列表以会话标题为主，辅以品牌、时间、会话数、结果与体积；进入单次详情后通过标题旁的返回按钮或 Esc 返回历史列表，再返回候选页。正文居中且最大宽度 720px，使用与 Settings 一致的分组面板；详情通过结果摘要、会话面板、整行文件位置展开控件组织信息。文件位置默认折叠，错误原因直接可见；已全部还原时不显示废纸篓与恢复按钮。纯浏览不重置筛选和列表位置，执行或恢复后回候选页再刷新文件状态。
- 点击会话标题，在主区域进入原有正文阅读器，保留侧栏；来源行中的返回按钮和 Esc 均可返回。列表不再常驻预览／源文件两个图标，也不使用预览弹窗。进入清理页不自动加载正文，返回保留勾选、筛选和原列表位置。源文件明细移到清理确认框，每个会话下按需展开；文件名和父目录分行、体积右对齐，完整路径支持悬停。

### Filter / Sort 的分工

- **Filter / 筛选**：纯 `sliders-horizontal` 图标按钮打开单层分组面板，悬停显示 Filter / 筛选，与 Sort、刷新保持相同工具栏样式。创建时间、更新时间及各自时长、Agent 和项目直接展示选项，不嵌套下拉菜单。选中项带勾及低饱和蓝色背景；条件改变立即更新结果，面板保持打开，“完成”、Escape 或点击外部收起。项目较多时在面板内滚动。当前时间和来源条件显示在标题下方。
- **Sort / 排序**：紧邻 Filter，与 All Sessions 使用相同的 `arrow-up-down` 图标、ghost 按钮、180px 最小菜单宽度及右对齐锚点。上半部分为 Date updated / Date created / File size（更新时间 / 创建时间 / 文件大小）；分隔线下方为 Descending / Ascending（降序 / 升序）。字段与方向分别显示勾选，选中后收起，tooltip 复用“排序：字段 · 方向”。
- 两个按钮都提供本地化 tooltip 和可访问名称。当前筛选激活态用 primary 色，排序状态通过 tooltip 与菜单勾选表达。收起后不常驻展示整排下拉表单。

### 与现有 Wake 设计保持一致

以现有 `workbench.rs` 列表排序菜单、`ui.rs` 常量和 `theme.rs` 为实现基准：

- 保持 224px 侧栏，主区水平留白 24px，使用与 Insights 相同的 `background` 页面底色；普通资料库继续使用原有三栏结构。
- 页面标题通过 `library_header` 与 All Sessions、Insights 共用：高度 88px、22px 标题、11px 副行、2px 行间距，操作对齐标题首行并保留窗口拖拽区。不再设置独立分类工具栏。Filter / Sort 图标为 16px、透明 ghost 常态、6px 圆角。
- 64px 会话行中，标题与来源组成两行，来源复用现有 15px 品牌图和项目徽章。日期列 112px、文件大小列 88px，数值右对齐，不保留独立操作列。日期列跟随当前排序；按文件大小排序且仅限制创建时间时显示创建时间，其余情况显示更新时间，悬停可见两项完整时间。标题随窗口伸缩，包含子会话时显示紧凑数量。
- 不增加列表外框或逐行横线，使用留白对齐区分会话；行高亮左右留 16px、内部留 8px，内容与页面 24px 边距对齐；勾选与悬停沿用现有材质和 8px 圆角。候选平铺，不强加 Today 等时间分组。底部与侧栏统一为 44px（包含顶部 hairline），摘要用 11px Label 字阶，选择前后列表高度不跳动。
- 页面内预览复用来源行、标题、元信息及正文阅读器。完整创建/更新时间、文件体积和清理范围放入现有元信息层；助手正文平铺，用户使用右对齐引用块，不重复显示 Agent 署名。
- 用现有 list / background / popover 材质区分区域；字号、颜色、间距分别使用 `FONT_*`、语义主题 token 和 4px 网格，按钮沿用既有组件。
- 阴影只用于弹出菜单/确认框；不加装饰图标、统计卡片或清理专用配色。结果页共用页面标题与 24px 边距，空状态复用现有空状态组件；文件结果与底部操作分别布局，文件结果单独滚动，恢复和继续操作保持可见。桌面实现保持原有最小窗口。
- Filter / Sort 作为英文源文案，经现有 i18n 层输出中文；不在产品界面里显示实现说明。

## 候选与排序

筛选决定候选范围，排序决定这些候选的排列。通过 Filter 按时间和来源收窄候选；排序独立提供以下三个字段，方向通过菜单底部的降序 / 升序选择：

| 排序选项 | 顺序与口径 |
| --- | --- |
| 创建时间 | 使用根会话的来源创建时间；升序优先查看很久以前开始的会话 |
| 更新时间 | 使用整棵会话树的最近更新时间；升序优先查看长期没有活动的会话 |
| 文件大小 | 使用整棵会话树可清理文件的体积；降序优先查看占空间最多的会话 |

首次默认“文件大小 + 降序”，之后记住用户的排序字段和方向。切换字段保留当前方向；切换字段或方向都保留勾选、当前预览和候选范围，选中文件的总量不变，不自动选择或排除任何项。旧版本未记录方向的偏好保留原有日期升序、体积降序结果。

同值按稳定 key 排列，避免刷新时跳动。创建时间使用来源中的 `created_at`，不能用文件复制到本机的时间代替；日期未知的记录不匹配有截止日期的筛选，但选择“不限”时仍可出现。创建时间筛选只判断创建时间，不附加隐藏的近期更新门槛。

### 时间条件

Filter 面板分别提供 **创建时间** 和 **更新时间** 两个独立条件，每个都直接选择“不限 / 30 天前 / 90 天前 / 180 天前 / 1 年前”。

- 首次默认“创建时间不限，更新时间 30 天前”；之后分别记住两项选择。1 年前按 365 天计算。
- 两项同时设置时取交集。例如“创建时间 180 天前 + 更新时间 30 天前”只保留至少 180 天前创建、且最近 30 天没有更新的会话。
- 创建时间取根会话的来源时间；更新时间取完整会话树的最大更新时间。各自只比较自己的截止时刻，未知日期不匹配该字段启用的截止条件。
- 截止时刻以进入清理或主动刷新时的本地时间为基准，本次审阅期间不随时钟自行移动。
- “不限”只取消对应日期的限制，不影响另一项；两项都不限才取消全部时间限制。没有额外的 7 天更新或文件修改时间门槛。文件在审阅后发生变化仍会中止该项清理。
- 页面副标题同时显示生效的日期条件。按文件大小排序时，仅创建时间有条件则展示创建日期，其他情况展示更新日期；按日期排序时展示对应排序日期。
- 旧 `time + days` 偏好迁移到对应日期项，另一项设为不限，保留原有候选范围。新偏好明确保存 `created_days` 和 `updated_days`；显式“不限”不会被默认 30 天覆盖。

时间筛选与 Sort 完全独立，改变排序不会更改任一日期条件。

### 筛选范围

Filter 统一提供创建时间、更新时间、排除收藏、排除置顶、排除无法清理、Agent 和项目。三个排除项默认均不勾选，改变后记住用户选择；范围包含整棵会话树。已生效的排除条件同时显示在页面副标题中。候选没有预设文件大小或对话轮数门槛；文件大小通过 Sort 排序比较。旧版保存的 All / Large / Short / Empty 偏好在加载时忽略，其他筛选和排序偏好继续保留。

Agents 与 Projects 均为多选：同组内取并集，不同组及日期条件取交集。未选任何值表示该组不限，不另设 All 选项。点击已选项可取消，搜索不清除选择；组标题显示整体选中数量，底部 Clear 清除全部筛选。旧版单选偏好转换为单元素集合，新版明确保存的空集合不会被旧偏好覆盖。

多选视觉统一为原 Agents 的轻量选项块：Exclude、Agents 与 Projects 共用 28px 行高、12px 文字、浅蓝选中底色与右侧勾号，未选中时使用浅中性底色和细边框，不使用方形复选框。Exclude 标题独立一行，下方排列等宽的 Starred、Pinned 与 Unavailable 选项。Unavailable 复用原 Only cleanable 的筛选逻辑与保存偏好，从标题右侧移入排除组；不勾选时继续展示无法清理的会话及原因。Agent 图标保留在名称左侧。来源分组增加分隔线，搜索框宽 284px，右对齐在 Sources 标题旁，明确其仅搜索来源的范围。

改变筛选条件后，清空勾选并重新计算候选数与体积；仅改变排序时保留勾选。首版使用时长快捷项，自定义日期留到后续。

候选行保持两行密度，展示标题、文件体积、Agent、项目与当前排序对应的时间。用户输入次数、子会话构成和完整时间通过页面内阅读器审阅，源文件明细放在清理确认框。

项目路径不存在和内容相似，不足以证明会话可删。第一版不做基于这两类信号的自动推荐。

## 统计口径

### 会话与内容

- 以完整会话树为选择和执行单位，包含来源已归档的后代。树的更新时间取全部成员的最大值。
- 有效用户输入沿用 Insights 的主线输入口径，排除系统提示、压缩摘要、工具返回等；不能直接将 `message_count` 当作用户输入次数。
- 解析失败、加密正文、格式不支持和未知计数不能算作空会话；清理前检查无法可靠识别的内容，逐项说明原因并跳过。
- 日期未知时不匹配指定的时间截止条件；“不限”可展示日期未知项。无法确认完整会话树的项直接在列表行中说明原因。

### 空间

- 后台读取确认属于会话的实际文件元数据后展示候选。候选总量、选中总量和最终摘要使用同一份去重后的目标集合。
- 对主文件、专属边车、子会话文件聚合；目录与其中的文件不重复计数。共享文件、硬链接、稀疏文件等不能简单相加推导必然释放的字节数。
- 能取得实际磁盘分配大小时优先使用；只能取得逻辑文件长度时明确标成“文件大小估算”。未知体积显示未知，不能当作 0。
- 不把 SQLite 会话逻辑字节数、缓存副本大小或 Wake 索引大小加进可清理空间。
- 界面显示“候选文件约 X MB”“选中文件约 X MB”；不提前显示“已释放 X MB”。

## 显式筛选与清理能力

收藏、置顶和日期属于用户可调整的 Filter 条件，不属于固定排除规则。默认只应用面板和副标题可见的“更新时间 · 30 天前”，收藏和置顶均可出现在列表中。两项时间都选择“不限”后，最近更新和日期未知的记录也可出现。候选及确认清单沿用 All Sessions 的星标、置顶图标，任一子会话有标记也会显示，标题 tooltip 说明含有相应标记的会话。

不可独立操作的来源仍不可清理，包括远程会话、共享数据库、路径归属不明、源文件缺失或会话树不完整。这些会话与可清理项在同一列表展示，创建时间、更新时间、Agent、项目及收藏／置顶条件对两类条目都生效；无法清理树的更新时间和标记从已知父子关系汇总。列表使用相同日期排序，大小未知显示「—」并在大小升降序中均置后。无法清理行禁用复选框，简短原因显示在来源信息之后，完整说明可悬停查看；标题和预览正常可用，不再使用分组展开或原因弹窗。

列表统计限定于当前筛选结果：44px 单行栏中的全选复选框标明可清理数量，旁边显示总会话数与无法清理数量；可清理文件体积移到底部未勾选摘要。全选、选中汇总及清理检查只接收 `CleanupCandidate`，无法清理的展示条目不会变成清理目标。Filter 标题右侧提供「仅显示可清理」，默认关闭、可记忆，清除筛选时重置关闭；开启状态同时显示在页面副标题。

入口位置修订已通过应用测试（48 通过、1 忽略）、格式检查与 Clippy（保留原有警告），发布包重启后在 1180×760 和 940×620 窗口核对统计栏、原因弹窗及精简后的 Filter。验证后恢复正常窗口与原筛选条件，未移动真实会话文件。

后续页内展开修订通过相同的测试与检查。原生验证覆盖展开／收起、原候选滚动位置恢复、已选候选跨分组保持正确，以及零候选时展开原因／收起为空状态。1180×760 和 940×620 下原因行均正常；最终恢复正常窗口和原筛选条件，清空验证勾选并保留页内展开供查看，未移动真实会话文件。

执行前核对会话树、收藏/置顶状态及文件指纹是否与审阅快照一致；期间发生变化则跳过并说明原因。索引事务核对的是审阅时的标记值，允许用户明确选中并审阅的收藏/置顶会话完成清理。没有最近修改时间并不能可靠说明 agent 已退出。

## 审阅与清理流程

1. 进入时展示符合时间及来源条件的候选，所有候选默认不勾选。
2. 行末按钮按需打开正文预览或文件清单；复选框决定是否清理。支持键盘和明确的全选候选，跨页选择用稳定 key。
3. 底部实时汇总选中根节点数、包含子会话后的总数、预计处理文件数与体积。
4. “清理…”先逐项检查选中会话，再展示最终文件清单和原路径，明确子会话、边车文件、体积和对恢复原会话的影响。检查失败不提前中断整批：确认框逐项列出将跳过的会话与原因，只统计实际可清理项的数量和体积；全部失败时只显示原因与刷新入口，不提供删除操作。
5. 最终主按钮为 **移到废纸篓**，沿用各系统平台文案和 danger 样式。
6. 后台按树执行，进度显示文件或会话处理数；成功、跳过和失败分别报告。取消只停止尚未开始的项。
7. 结果页明确显示“已移到废纸篓 X MB，空间回收待完成”，提供打开系统废纸篓及查看本批原文件清单的入口。

### 真正释放空间

移到系统废纸篓通常不会立即释放磁盘空间，因此“移动成功”不能成为“已释放空间”的完成文案。

用户在系统废纸篓中确认删除本批文件后，才完成不可恢复的空间回收。结果页要显式说明此最后一步；不能默认清空用户整份废纸篓，因为其中可能包含与 Wake 无关的文件。首版不提供后台定时永久删除。

如果未来要提供 Wake 内“一步永久删除”，需单独设计仅针对当前计划的永久删除和明确确认流程；它不是当前 Trash 服务的隐含行为。开发验证使用合成文件，不清理用户的真实会话。

## 执行与恢复

### 计划与复核

`CleanupCandidate` 保存会话 key、来源实例、完整后代集合、保护状态、实际文件目标、身份与修改指纹和大小；`CleanupBatch` 保存本次审阅的候选快照及逐目标执行状态。

执行前重新核对：会话更新、新增子会话、收藏/置顶状态变化、路径归属变化时跳过整棵树并解释原因。共享路径不能连带未选择会话；不明确时不支持清理。找不到 adapter 时不得降级成直接删除 `file_path`。

### 部分失败

文件系统和索引数据库不能共用一个原子事务，不能把整份列表塞进一次 `trash_paths` 后只显示整批成功或失败。

按树执行、逐目标记录结果；确认树内文件动作全部完成后，再完成索引事务和删除标记。部分移动成功或索引失败时记录真实状态，可重试、可核对，不能假装完全回滚。处理中断后按持久操作记录恢复状态。

### 从废纸篓恢复

清理记录提供原路径、受影响会话和文件状态。恢复由系统废纸篓完成：在 macOS Finder 中选择“放回原处”，再点击 Wake 的 **Check**。顶部结果卡片显示一句操作说明及纯文字 **Trash／Check**，不再提供自动 Restore。

Check 只检查原路径的会话与关联文件。完整性及来源验证通过后，清除仅属于本次删除的 tombstone，并触发增量扫描；它不读取废纸篓、不移动文件。文件尚未放回时显示普通操作提示，不能声称恢复成功。旧自动恢复的权限错误保留在历史数据中，界面以当前的手动恢复说明替代裸错误堆栈。

已永久删除的文件无法恢复；后续删除标记、格式不符和文件缺失仍会阻止重新收录。历史数据保留，索引重建不能删除它。

## 实现边界

### wake-core

- 新增 `cleanup.rs`：候选、会话树筛选、独立文件清理能力、空间估算、计划与执行结果。
- adapter 显式返回可独立清理的路径或不支持原因；能力按具体来源判断，远程装饰器始终拒绝文件删除。

- 先读索引，再后台核实授权范围内的源文件。无需 LLM 或网络。

### wake

- 独立清理视图与状态模块，复用正文阅读器、字体和颜色规范，不把整个功能继续堆进 `workbench.rs`。
- 阈值、排序等偏好使用 Store `prefs`，不使用启动前的 `prefs.rs`。
- 英文源文案和中文翻译同步；系统废纸篓名称按平台提供。
