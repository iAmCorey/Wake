# 本机会话文件清理

计划版本：0.7.0，尚未发布。

## 目标与范围

帮助用户按时间和磁盘占用找到不再需要的本机会话，审阅后移入系统回收站。会话是否仍有价值由用户判断，不做自动推荐或后台删除。

只支持 adapter 明确声明可独立清理的主文件、专属关联文件和完整子会话树，包括本地归档。远程会话、远程镜像、共享数据库、全局缓存、模型文件和项目工作目录不属于清理范围。无法清理的会话仍在列表中展示，并说明原因；删除 Wake 索引不算释放源文件空间。

## 页面与筛选

- 入口位于侧栏底部，沿用应用的页面背景、24px 内容留白、标题和两行列表密度，不增加第二列。
- Filter 与 Sort 独立。创建时间、更新时间分别提供不限、30 天前、90 天前、180 天前和 1 年前，两个时间条件取交集。日期未知时只能匹配“不限”。
- Agents、Projects 均支持多选：同组取并集，不同组取交集；未选表示不限，不增加 All 选项。来源选项取完整清理清单，包含归档和不可清理项，不随当前过滤结果缩减；已选但暂时消失的来源仍可取消。
- Exclude 包含 Starred、Pinned、Unavailable，默认均关闭。收藏和置顶是显式筛选条件，不是隐藏的保护规则。标记与更新时间按完整会话树汇总。
- Exclude、Agents、Projects 共用轻量选项块：浅中性底色和细边框表示未选，浅蓝底色与尾部勾号表示选中；Agent 保留品牌图标。来源搜索放在 Sources 标题旁，只搜索来源选项，不清除已选值。
- Sort 复用 All Sessions 的菜单结构，分别选择创建时间、更新时间、文件大小及升降序；未知值始终在最后。排序保留选择，修改筛选清空选择。
- 首次使用默认“更新时间 · 30 天前”。Clear 清空筛选；筛选和排序可保存，旧单日期／单来源偏好自动迁移。

列表顶部显示全选、当前会话数及不可清理数量。不可清理行显示禁用复选框和简短原因，悬停可看完整说明，标题仍可打开阅读器。全选只选择当前范围内可清理的会话。未选择时底部显示可清理文件体积；选择后显示汇总及 Clear／Delete。

点击标题复用现有阅读器。Back／Esc 返回清理页，保留筛选、选择和滚动位置。每次正文加载使用独立请求编号，避免原阅读器和清理预览互相覆盖异步结果。

文字操作统一为纯文字按钮，与应用现有尺寸一致：32px 高、12px 水平留白、6px 圆角。删除采用 danger 样式，最终确认按钮为 Confirm。筛选／排序／刷新、返回和展开仍使用功能图标。

## 审阅和执行

1. Delete 在后台检查所选会话，并显示进度；检查完成后打开确认清单。
2. 确认清单展示会话、包含的文件数量和体积；文件位置按需展开。失败项逐项说明原因并跳过，全部失败时只提供刷新，不提供执行按钮。
3. 固定底部说明恢复方式和空间释放条件，操作为 Cancel／Confirm；只有 Confirm 开始移动文件。
4. 执行以整棵会话树为单位、以独立文件目标为步骤。每步先持久化状态，再调用现有系统 Trash 服务；取消只停止尚未开始的会话树。
5. 整棵树的目标全部确认移动后，索引事务写入删除标记。部分失败和索引失败分别记录，不能把部分成功当作完整回滚。

移入回收站通常不会立即释放空间。只有用户在系统回收站删除这些文件后，才完成空间回收。Wake 不清空整个回收站，也不在回收失败时改用永久删除。

## 文件归属与复核

`CleanupCandidate` 保存完整会话树、用户标记、目标路径、文件类型、身份、修改时间和大小快照。生成清单时读取完整索引元数据，主线输入统计单独批量聚合；执行复核不重复聚合消息表。

执行前重新检查会话树、收藏／置顶、来源启用状态、路径包含关系和完整文件快照。任何其他会话对目标的所有权都必须纳入考虑，包括当前过滤范围外的会话。符号链接、共享硬链接、路径归属不明和无法完整解析的会话不能清理；解析后再次核对文件与索引元数据。

新删除记录在第一次移动前，为所有普通文件生成 SHA-256 并保存到日志。读取大文件后再次核对归属和快照。日志先于文件移动持久化，异常或中断后可按逐目标状态判断已完成和待处理项。

## 空间统计与平台差异

- Unix 使用设备号／inode 识别文件，以分配块数统计磁盘占用，并排除共享硬链接。
- Windows 从文件句柄获取卷编号和完整 128 位文件 ID，支持 ReFS 身份；同时核对硬链接数和重解析点。普通文件使用分配空间，压缩／稀疏文件使用压缩信息，不能以逻辑长度或零身份作为回退值。
- Windows 的 UNC、扩展 UNC、映射网络盘在清单和执行前均说明不可清理原因。非固定卷无法保证安全回收，也不进入候选；服务层在移动整个批次前再核对位置。
- macOS 使用现有 Finder Trash 服务；Linux 使用 freedesktop Trash 实现；Windows 使用系统 Recycle Bin 服务。新平台必须显式实现服务，不继承其他系统的行为。
- 大小按目标集合去重，目录本身不重复计入文件内容大小。体积表示所选文件占用，不承诺移动后立即释放同样的空间；共享文件系统块等因素仍由系统决定。

## 历史与恢复

History 是独立页面，按批次展示会话、时间、体积和状态。详情展示结果摘要、各会话的处理状态及可展开的原文件位置。Trash／Check 位于结果卡片内，全部恢复后隐藏无关操作。

恢复由用户在系统回收站完成，再点击 Check。Check 不读取回收站、不移动文件、不覆盖已有内容；它只验证原位置的文件并清除属于本次删除的标记，随后重新扫描。

新记录验证主文件及全部关联文件的路径、类型、逻辑长度与内容摘要，再解析会话并复核快照。缺失文件、目录冒充文件、同长度但内容不同的替换文件都不能标为已恢复。系统跨卷还原产生新 inode／文件 ID 或不同分配量，不影响合法恢复。

旧日志没有内容摘要，兼容检查只能核对类型、长度、修改时间及主会话解析，无法事后证明旧关联文件的逐字节内容。旧自动恢复的权限错误显示手动恢复指引；真正的移动或索引失败仍保留错误信息。不提供应用内自动 Restore：开发目录测试通过无法保证系统允许读取用户已有的回收站目录。

## 验证要求

- 合成文件测试覆盖完整树、源归属、共享文件、同大小同时间的文件替换、取消、部分失败、索引重试和旧日志兼容。
- 恢复测试覆盖缺失关联文件、错误类型、内容不符、符号链接、跨文件身份还原，以及后续删除标记不能被旧历史清除。
- Windows 专属测试覆盖路径前缀、本地卷、网络位置以及稀疏／压缩分配量。Cursor CLI 与 IDE 数据库的路由须独立验证；数据库会话不能进入文件候选。
- CI 在 macOS、Linux、Windows 运行核心测试、应用逻辑测试和构建。Linux／Windows 另显式执行真实系统回收站往返测试，只处理本次唯一临时目录的合成文件，不处理其他条目。
- UI 验证包含列表、筛选、阅读器返回、确认框和旧历史兼容，不移动真实会话文件。跨目标类型检查不能替代原生系统运行结果。
